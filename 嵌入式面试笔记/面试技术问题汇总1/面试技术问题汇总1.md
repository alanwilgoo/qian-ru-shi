### <span style="color: #C00000">TCP 与 UDP 的区别</span>

TCP（传输控制协议）是一种面向连接的、可靠的、基于字节流的传输层通信协议。在使用TCP进行通信时，发送方和接收方需要先建立连接（通过三次握手），在通信结束后断开连接（通过四次挥手）。TCP提供了可靠的、顺序的、无差错的数据传输，通过确认、重传、流量控制和拥塞控制机制保证数据传输的可靠性。

UDP（用户数据报协议）是OSI参考模型中无连接的传输层协议，提供简单、不可靠的信息传输服务。UDP不进行连接建立和断开，发送方和接收方直接发送和接收数据报文。UDP没有流量控制和拥塞控制，因此适用于实时性要求较高、但对可靠性要求较低的应用，如视频流、语音通话等。

**总结：**TCP适用于需要可靠传输和数据完整性的场景，而UDP适用于对速度要求较高但可以容忍丢包的应用。

### <span style="color: #C00000">无符号16位和有符号16 位的取值范围</span>

**无符号16位整数（Unsigned 16-bit）**  
无符号16位整数的范围为 0 到 65535。由于没有符号位，所有16位都用于表示数值。二进制表示为：  
0000 0000 0000 0000 到 1111 1111 1111 1111，即十进制的范围是 0 到 2^16 - 1。

**有符号16位整数（Signed 16-bit）**  
有符号16位整数使用补码表示，最高位（最左边的一位）表示符号位。其取值范围为 -32768 到 32767。

-   最大负数为 -2^15，即 -32768，其二进制表示为 1000 0000 0000 0000（补码表示）。
-   最大正数为 2^15 - 1，即 32767，其二进制表示为 0111 1111 1111 1111。  
    二进制范围为：1000 0000 0000 0000 到 0111 1111 1111 1111，即十进制的范围是 -2^15 到 2^15 - 1。

### <span style="color: #C00000">简述三次握手和四次挥手，如果客户端断开出现故障怎么办？</span>

**三次握手：**

1.  **客户端发送SYN包：**客户端发送一个带SYN标志的报文，告诉服务器请求建立连接，并且带有一个初始序列号（ISN）。
2.  **服务器回应SYN+ACK包：**服务器接收到客户端的SYN包后，响应一个SYN+ACK包，表示同意连接并返回自己的序列号。
3.  **客户端发送ACK包：**客户端收到服务器的SYN+ACK包后，发送ACK包确认连接建立，至此，连接正式建立。

**四次挥手：**

1.  **客户端发送FIN包：**客户端发送一个带FIN标志的数据包，请求关闭连接。
2.  **服务器响应ACK包：**服务器收到客户端的FIN包后，回应ACK包，确认客户端的关闭请求，但此时连接尚未完全断开。
3.  **服务器发送FIN包：**服务器完成数据传输后，发送一个FIN包给客户端，表示准备关闭连接。
4.  **客户端回应ACK包：**客户端收到服务器的FIN包后，发送ACK包确认，连接关闭。服务器在收到此ACK后，完全断开连接。

**故障处理：**

如果客户端突然断电或崩溃，服务器将等待一段时间（TIME\_WAIT状态）来确保客户端完成连接关闭。如果客户端未能正常断开，服务器会在超时后清理连接。

如果客户端没有收到ACK或FIN包，可能会进行超时重传，确保连接最终正常关闭。

### <span style="color: #C00000">网络的七层模型（OSI模型）是什么？</span>

**口诀**：  
**物数网传会表应**  
这帮助记住七层的顺序：物理、数据链路、网络、传输、会话、表示和应用层。

**网络的七层模型（OSI模型）**： OSI模型是一个网络通信模型，将网络协议和通信过程分为七个层次：

1.  **物理层（Physical Layer）**：负责数据的物理传输，如电缆、无线信号等。
2.  **数据链路层（Data Link Layer）**：负责在物理层之间提供可靠的数据传输，进行错误检测与修正。
3.  **网络层（Network Layer）**：负责数据的路由选择和转发，使用IP地址。
4.  **传输层（Transport Layer）**：确保数据的可靠传输，如TCP（可靠）和UDP（不可靠）。
5.  **会话层（Session Layer）**：管理应用程序之间的会话，确保数据同步。
6.  **表示层（Presentation Layer）**：负责数据的格式化、加密和解密。
7.  **应用层（Application Layer）**：直接与用户交互，提供各种应用服务，如HTTP、FTP等。

### <span style="color: #C00000">互斥锁的作用，为什么出现死锁（互斥锁的知识）</span>

**互斥锁的作用：** 互斥锁是专门用于处理线程互斥的一种机制。它用于保护临界资源，确保同一时刻只有一个线程能够访问该资源。互斥锁有两种状态：上锁状态和解锁状态。如果互斥锁处于上锁状态，其他线程会被阻塞，直到当前锁被解锁；如果锁处于解锁状态，则可以正常上锁，不会阻塞。

**死锁的原因：** 死锁指的是由于线程间资源请求的循环依赖，导致线程无法继续执行。**死锁发生的四个必要条件包括：**

1.  **互斥条件：**至少有一个资源必须处于被独占的状态。
2.  **请求与保持条件：**线程已经持有某些资源，同时等待其他资源。
3.  **不剥夺条件：**已获取的资源不能被强制剥夺。
4.  **循环等待条件：**形成资源请求的闭环，多个线程相互等待。

**死锁的解决办法包括：**

1.  **避免死锁：**通过确保线程按照相同的顺序请求资源，或者使用锁超时机制，避免形成死锁。
2.  **死锁检测：**通过周期性检测资源分配图，检查是否存在循环等待。
3.  **死锁恢复：**如果死锁已经发生，可以通过中止线程或回滚操作来释放资源，恢复系统运行。

### <span style="color: #C00000">I2C的通信过过程 （起始信号->地址->数据->结束信号）</span>

I2C通信过程（起始信号 -> 地址 -> 数据 -> 结束信号）  
I2C（Inter-Integrated Circuit）是一种同步串行通信协议，常用于微控制器与各种外设之间的通信。I2C通信通常包括两个阶段：主设备向从设备写数据和主设备从从设备读数据。

**主设备向从设备发送数据：**

1.  **起始信号（START）：**主设备发送一个起始信号，SDA线由高电平拉低，SCL保持高电平，标志着通信的开始。
2.  **设备地址：**主设备发送从设备的地址，地址通常是7位或10位，地址后跟随一个读/写位（0表示写，1表示读）。
3.  **响应（ACK）：**从设备收到地址后，回应一个ACK信号，表示准备好接收数据。
4.  **数据传输：**主设备发送数据，每个字节的数据后，从设备需要发送ACK响应，表示数据接收成功。
5.  **停止信号（STOP）：**数据发送完毕，主设备发送停止信号，SDA线从低电平拉高至高电平，结束通信。

**主设备从从设备接收数据：**

1.  **起始信号（START）：**主设备发送起始信号。
2.  **设备地址：**主设备发送从设备的地址并设置读位（1），表示读取数据。
3.  **响应（ACK）：**从设备收到地址后响应ACK。
4.  **数据接收：**主设备接收数据，每接收一个字节后，发送ACK给从设备，表示继续接收数据。接收到最后一个字节时，主设备发送NACK，表示数据接收完成。
5.  **停止信号（STOP）：**接收完所有数据后，主设备发送停止信号，结束通信。

**I2C双向通信：**  
I2C使用两条线：数据线（SDA）和时钟线（SCL）。时钟线由主设备控制，数据线是双向的，数据传输在时钟的同步下进行。在每个时钟脉冲的高电平期间，数据位在SDA线上稳定。

### <span style="color: #C00000">Static 关键字的作用</span>

**static局部变量：**

改变了变量的生命周期。普通的局部变量在每次函数调用时创建，并在函数返回后销毁。而static局部变量在程序的整个运行期间都存在，且只会初始化一次，保持函数调用之间的值。

存储位置：static局部变量虽然定义在局部作用域中，但它存储在数据段，而不是栈上。

**static全局变量：**

改变了变量的作用域，使得该全局变量只能在定义它的源文件中访问，其他源文件无法使用该变量。这有助于避免全局变量名称冲突，并提高代码的模块化。

存储位置：static全局变量存储在数据段，但它的作用域仅限于当前文件。

**static函数：**

改变了函数的作用域，使得该函数只能在定义它的源文件内访问，无法被其他源文件调用。这有助于避免命名冲突和不必要的外部依赖。

存储位置：static函数存储在代码段，但是它的链接性被限制在当前源文件内。

### <span style="color: #C00000">C语言的static和C++关键字static有什么区别</span>

**C语言中的static关键字**

**static局部变量：**static局部变量的值在函数调用之间保持不变，只初始化一次，程序运行期间一直存在。存储位置：存储在数据段。

**static全局变量：**static全局变量的作用域仅限于定义它的文件，不能被其他文件访问。

**static函数：**static函数的作用域仅限于定义它的文件，其他文件无法调用这个函数。

**C++中的static关键字**

**static局部变量：**与C语言中的static局部变量类似，在函数调用之间保持其值，仅初始化一次。存储位置：存储在数据段。

**static全局变量：**与C语言相同，作用域仅限于定义它的文件，不能被其他文件访问。

**static成员变量：**static成员变量属于类，而非类的某个对象。所有类的对象共享一个静态成员变量。初始化必须在类外部初始化。

**static成员函数：**static成员函数只能访问静态成员变量和静态成员函数，不能访问非静态成员变量和this指针。

**static局部变量在类成员函数中的使用：**static局部变量在类成员函数中与其他语言相同，跨函数调用保持其值。

### <span style="color: #C00000">纯虚函数有什么作用？如何实现？</span>

**纯虚函数的作用：**

**规范接口：**纯虚函数用于在父类中声明一个接口，要求所有派生类必须实现该接口。它定义了一个必须实现的行为规范，确保了所有派生类具有相同的接口。

**抽象类：**当一个类中包含纯虚函数时，这个类就变成了抽象类。抽象类不能直接实例化对象，只能通过派生类来实现和创建对象。

**派生类实现：**如果派生类没有实现父类的纯虚函数，派生类仍然是抽象类，不能实例化。

**多态性：**纯虚函数使得多态性得以实现，不同的派生类可以根据自己的需要提供不同的函数实现。

**如何实现纯虚函数：**

在父类中声明纯虚函数，纯虚函数没有函数体，它只是一个接口的声明。派生类必须提供纯虚函数的具体实现。

派生类必须实现父类中的所有纯虚函数，否则派生类也会变成抽象类，无法实例化。

**总结**

纯虚函数用来定义接口，强制派生类实现特定的行为。

含有纯虚函数的类是抽象类，不能直接实例化对象。

只有当派生类实现了所有纯虚函数，才能实例化对象。

纯虚函数在声明时使用= 0标记，并且在父类中没有实现。

### <span style="color: #C00000">std::vector 和 std::list 的区别（什么情况下用 vector，什么情况下用list）</span>

**存储方式：**

std::vector：元素在内存中连续存储，使用动态数组实现。

std::list：元素在内存中非连续存储，使用双向链表实现。

**访问速度：**

std::vector：支持常数时间复杂度的随机访问（O(1)），适合频繁的元素访问。

std::list：不支持常数时间的随机访问，访问时间复杂度是 O(n)。

**插入和删除：**

std::vector：在末尾插入和删除通常为 O(1)，但是在中间或前部插入和删除需要移动元素，时间复杂度为 O(n)。

std::list：在任意位置插入和删除元素都为 O(1)（假设你已经找到位置），但由于链表结构不支持快速访问元素，因此访问某个位置的时间复杂度是 O(n)。

**内存使用：**

std::vector：由于使用连续的内存块，内存更加紧凑，通常比 std::list 更节省内存。

std::list：每个元素除了存储数据，还需要存储指向前后节点的指针，因此内存开销较大。

**使用 std::vector：**

当你需要 高效的随机访问（例如频繁使用下标操作访问元素）。

当你仅需要 在末尾进行插入和删除 操作（例如栈或队列实现）。

当元素数量事先大致确定，并且不需要频繁在中间进行插入或删除时。

**使用 std::list：**

当你需要 频繁在中间进行插入或删除 操作时，特别是在大数据量的情况下。

当你不需要 频繁进行随机访问，或者只需要在列表的两端进行操作。

当你需要双向遍历或其他链表特性时（例如需要从尾部开始遍历）。

**总结：**

std::vector 适用于需要高效随机访问和末尾操作的场景，且内存开销较低。

std::list 适用于频繁在中间进行插入和删除操作的场景，但随机访问效率较低，且内存开销较大。

### <span style="color: #C00000">typedef 和 #define 的区别</span>

**typedef：**用于给一个已有的数据类型起一个别名，它仅仅是类型的重命名。其作用范围仅限于声明它的文件或作用域内。创建的是类型别名，不会影响程序运行，编译器进行类型检查；用于提高代码的可读性，特别是当类型复杂时。

**#define：**预处理指令，用于定义宏。它可以定义常量、表达式或者代码片段，宏在编译前通过预处理器进行文本替换。#define 定义的是一个宏，不是类型别名，宏在预处理阶段进行文本替换，不进行类型检查。宏可以是常量、函数或更复杂的表达式，适用于条件编译和其他预处理操作。

**总结：**

typedef 用于 类型别名，并进行 类型检查，适用于提高代码可读性和简化复杂类型名称。

#define 用于 宏定义，在 编译前进行文本替换，适用于定义常量、表达式和条件编译。

### <span style="color: #C00000">进程和线程的区别</span>

**进程：**

进程是操作系统分配资源的基本单位，是 程序的执行实例。当程序运行时，操作系统为其分配资源（如内存、文件描述符等），并形成一个执行中的进程。每个进程都有自己的 独立地址空间 和 资源。

进程之间是相互独立的，一个进程的崩溃不会直接影响到其他进程。

进程间通信（IPC）相对复杂，因为进程拥有独立的内存空间。

**线程：**

线程是 进程内的执行单元，每个线程拥有自己的 程序计数器、寄存器 等，但多个线程共享同一进程的 内存空间 和 文件描述符 等资源。

线程切换的开销较小，适合需要高效并发执行的场景。

由于线程间共享资源，它们之间的 通信 更加高效，但也容易发生 竞态条件 等问题，因此需要使用同步机制（如互斥锁、信号量等）来保护共享资源。

**总结：**

进程是操作系统资源分配的基本单位，具有独立的资源和地址空间。

线程是进程内的最小执行单元，线程间共享进程的资源，因此切换开销较小，适合并发执行任务。

### <span style="color: #C00000">重载，重写，重定义的区别</span>

**重载（Overloading）**：指在同一作用域内，多个函数有相同的函数名，但参数列表不同。重载的函数签名必须不同，参数个数或类型的不同会使得它们成为不同的函数。**返回类型不影响重载**。

**重写（Overriding）**：发生在继承关系中，子类重写父类的虚函数。子类中的重写函数与父类的虚函数必须有相同的函数签名（包括函数名、参数类型和返回类型），并且使用 virtual 关键字声明父类中的函数。通过重写，父类指针或引用指向子类对象时，会调用子类中重写的虚函数，实现动态多态。

**重定义（Hiding）**：重定义，或称为隐藏，发生在子类中当子类定义了一个与父类同名的函数（即使参数列表或返回值不同）。在这种情况下，子类的同名函数会隐藏父类中的同名函数。子类的函数不会参与多态机制，也不会被虚函数机制动态绑定。

### <span style="color: #C00000">引用与指针的区别</span>

**引用不可以为空，但指针可以为空：**引用 一旦初始化后，必须始终引用一个有效的对象，不能为 null。而 指针 可以为空，表示它不指向任何对象或指向无效的内存地址。

**引用不可以改变指向，对一个对象“至死不渝”；但指针可以改变指向：**引用 在初始化时绑定到一个对象，并且不能再指向其他对象，即它是“固定”的。而 指针 可以随时指向不同的对象，可以动态修改其指向。

**引用的大小与指针相同，通常为 4 或 8 字节；指针是指针本身的大小：**引用 和 指针 的大小通常相同，因为引用底层实现通常是通过指针来实现的。尽管 引用 被认为是一个“别名”，但在内存中，它和 指针 一样存储的是地址。因此，在大多数架构中，引用和指针的大小通常是 4 或 8 字节（取决于系统架构）。

**引用比指针使用起来更直观和简洁：**引用 在使用时，不需要解引用符号（\*），直接通过引用变量名就可以访问对象内容，类似于普通变量。相比之下，指针 需要使用 \* 来解引用才能访问指向的对象。需要注意的是，在声明引用时，我们使用 & 作为声明符，但这并不代表引用的值是“取址”，而只是用于声明引用类型。

**引用比指针更安全：**引用 是更安全的选择，因为它不能为 null，并且一旦绑定到一个对象后，就不能再指向其他对象。但仍需注意，如果 引用 指向一个 已销毁或无效的对象，依然会导致 未定义行为。与此不同，指针 由于可以为空，因此需要开发者手动检查其有效性，避免访问无效地址。

### <span style="color: #C00000">系统IO与标准IO的区别</span>

**系统IO：**

系统IO操作是无缓冲的，数据在每次读写时都会直接从应用程序传递到内核，或者从内核传递到应用程序。每次读写操作都涉及系统调用，因此性能较低，且频繁访问系统资源。适用于处理字符设备或设备文件，例如串口设备或控制台，通常这些设备不支持缓存机制。由于没有缓冲区，系统IO通常需要手动管理数据刷新。

**标准IO：**

标准IO操作是有缓冲的。数据首先被写入内存中的缓冲区，系统会在适当时机（例如缓冲区满或程序结束时）自动将缓冲区的数据写入到内核。这样减少了对系统资源的频繁访问，提升了性能。标准IO通常用于普通文件（如文本文件）的读写，因为缓冲机制可以提高效率。在标准IO中，缓冲区的刷新由系统自动管理，因此开发者不需要手动干预。

**总结：**

系统IO更接近硬件，适用于低级设备和字符设备操作，但性能较低。

标准IO适用于普通文件操作，提供缓冲机制，提高了性能和效率。

### <span style="color: #C00000">简述大端存储和小端存储</span>

**大端存储（Big Endian）：**数据的低有效字节存储在内存的高地址，而高有效字节存储在低地址。许多网络协议（如TCP/IP协议）采用大端存储，这种存储方式更接近人类的书写顺序，从左到右。大端字节序常用于数据传输中的标准格式，尤其是在不同平台之间交换数据时，能确保字节顺序一致。

**小端存储（Little Endian）：**数据的低有效字节存储在内存的低地址，而高有效字节存储在高地址。在许多计算机体系结构（如Intel x86）中使用小端存储。它较为常见，因为在这种存储方式下，低位数据存储在内存的前面，这使得操作系统和应用程序在处理字节时更加高效。

### <span style="color: #C00000">简述 SPI 总线及 I2C 总线通信原理</span>

1\. **硬件连接：**SPI（Serial Peripheral Interface）：需要四根信号线：MISO（主入从出）、MOSI（主出从入）、SCK（时钟线）、CS（从设备选择线）；I2C（Inter-Integrated Circuit）：仅需要两根信号线：SDA（数据线）和SCL（时钟线）。

2\. **通信方式：**SPI：全双工通信，数据可以同时双向传输，适合高速数据传输。支持多个从设备连接，但每个从设备通常需要独立的CS线；I2C：半双工通信，使用两根共享的线进行双向传输，支持多主多从通信，但数据传输是分时的，即每次只能传输一个方向的数据。

3\. **传输速度：**SPI：传输速度较高，通常为几Mbps到几十MBps；I2C：传输速度相对较低，标准模式为100kbps，高速模式可达到3.4Mbps。

4\. **应用场景：**SPI：适用于需要高速数据传输的应用，如存储器、传感器、显示屏等；I2C：适用于连接多个低速设备，常用于微控制器与外围设备（如传感器、LCD、EEPROM）之间的通信。

**总结：**

SPI：全双工、高速、需要更多的线，适合需要高速数据传输的场合。

I2C：半双工、较慢、使用更少的线，适合连接多个低速设备。

### <span style="color: #C00000">数组和链表有哪些区别</span>

**1\. 空间的角度：**

**数组：**数组的大小在定义时是固定的，并且数组的大小在编译时已确定。例如，int a\[100\]，在这时就会固定数组大小为100。数组的元素在内存中是连续的，存储的是相同类型的数据。数组的内存空间是静态分配的，因此无法在运行时改变大小。

**链表：**链表在创建时节点的个数是不固定的，链表的大小是动态变化的。每个链表节点通常包含两个部分：数据部分和指向下一个节点的指针（或引用）。这些节点的内存地址是不连续的。链表内存是通过动态内存分配（如 malloc 或 new）来分配的，节点的内存空间大小在定义时并不确定，取决于节点的数量和结构。

**2\. 内存的角度：**

**数组：**数组中的元素在内存中是连续存储的，数组在内存中的地址是连贯的。访问数组的元素时，通过数组名加下标的方式来进行访问（如 a\[i\]），这是一个常数时间操作，访问速度非常快。如果数组需要表示线性关系（如排好序的元素），删除某个元素时，通常需要批量移动数组中的其他元素，这样操作的时间复杂度为O(n)。

**链表：**链表的节点在内存中是非连续存储的，每个节点都包含一个指向下一个节点的指针。访问链表的元素需要顺序遍历，即从头节点开始逐个节点访问，直到找到目标元素。访问速度相对较慢，时间复杂度为O(n)。链表的插入和删除操作效率较高，特别是在已知位置的情况下（无需移动其他节点）。

**3\. 申请空间的位置：**

**数组：**栈：如果数组是局部变量，它通常分配在栈上（例如：int a\[100\];）。栈上分配的内存空间大小在编译时确定。数据段：全局数组或静态数组则存储在数据段中，且其大小在编译时确定。

**链表：**链表的每个节点通常是在堆上动态分配内存（如使用 malloc、new 等方法），节点的数量和内存大小在运行时才能确定。

**4\. 操作的效率：**

**数组：**插入、删除元素的效率较低，因为删除元素时必须移动元素，时间复杂度是O(n)。查找元素效率较高，访问时间是O(1)，即通过下标直接访问。

**链表：**插入、删除操作效率高，尤其是在已知位置的情况下，时间复杂度为O(1)（不需要移动其他元素）。查找元素的效率较低，通常是O(n)的顺序查找。

**总结：**

**数组：**适用于已知大小且频繁访问元素的场景。由于数组的元素是连续存储的，它支持快速的随机访问，但不支持动态大小和高效的插入/删除操作。

**链表：**适用于动态数据结构，特别是插入和删除频繁的场景。链表支持灵活的大小调整，且可以在已知位置进行高效的插入和删除操作，但由于访问方式是顺序的，访问速度较慢。

### <span style="color: #C00000">内存泄露怎么产生的？如何避免？在一个功能应用要求频繁使用内存的场景，该如何有效的管理内存</span>

**内存泄漏的产生：**

内存泄漏是指程序动态分配的内存未正确释放，导致内存浪费和性能下降。它通常发生在堆内存中，尤其是在丢失指针或忘记释放内存时。常见原因包括：

**指针丢失：**分配内存后没有正确保存或释放指针。

**重复分配：**重新分配内存前未释放原内存。

**循环引用：**对象间相互引用，导致无法释放。

**如何避免内存泄漏：**

**手动释放内存：**每次使用malloc或new分配内存时，确保调用free或delete释放。

**智能指针（C++）：**使用std::unique\_ptr或std::shared\_ptr自动管理内存。

**RAII：**通过对象生命周期管理内存。

**内存池：**集中管理内存，减少分配/释放次数，避免碎片。

**内存管理策略：**

**内存池：**在频繁内存分配的场景下，通过预分配内存减少碎片。

**内存检测工具：**使用Valgrind、AddressSanitizer等工具检测内存泄漏。

**编码规范：**确保每次分配内存后都有对应的释放操作。

**动态分析：**使用工具分析程序运行时的内存分配，及时发现泄漏。

**总结：**

内存泄漏是由于动态内存管理不当引起的，通过智能指针、内存池、RAII原则和内存泄漏检测工具等方法，可以有效避免。尤其在高频内存操作的场景中，合理的内存管理至关重要。

### <span style="color: #C00000">extern 关键字的作用</span>

有以下作用：

**声明外部变量：**extern 关键字用于在当前文件中声明在其他文件中定义的全局变量或函数。这可以让多个源文件共享同一个变量或函数，而不需要重复定义。例如，在文件A中定义了一个全局变量，在文件B中使用 extern 来声明该变量，使得文件B可以访问文件A中的变量。

**共享变量或函数：**通过 extern，不同的源文件可以共享同一个变量或函数，使得程序模块化，便于维护和扩展。对于大型项目来说，将全局变量或常用函数放在独立的文件中，其他文件通过 extern 引用这些变量或函数，有助于代码的结构化和分离。

**链接阶段的可见性：**在编译阶段，extern 关键字声明的变量或函数在当前文件不可见，但在链接阶段，extern 的作用使得这些变量或函数在整个程序中可见。此时，编译器会将链接阶段需要的符号（变量或函数）连接到程序中。

**C风格函数的支持（extern "C"）：**当 extern 与 "C" 一起使用时，通常出现在 C++ 中，表示该函数遵循 C 的调用约定，而不是 C++ 的调用约定。这可以使 C++ 代码与 C 代码之间进行互操作，避免 C++ 编译器对函数名进行修改（名称修饰，name mangling）

**声明而非定义：**extern 用于声明变量或函数的存在，而不是定义它们。声明告诉编译器该变量或函数会在其他地方定义，编译器不需要为它们分配内存，只在链接时将它们解析到合适的内存地址。这对于避免重复定义和处理多个源文件之间的依赖关系非常重要。

**避免多重定义问题：**在C语言中，如果多个文件中都定义了相同的全局变量或函数，会导致链接时的多重定义错误。使用 extern 关键字可以避免这种情况，因为它只是声明而不是定义。因此，extern 通常用在头文件中，以便在多个源文件中共享同一变量或函数的声明。

**总结：**

extern 关键字在 C/C++ 编程中扮演着非常重要的角色，主要用于以下几个方面：

**声明外部变量/函数：**允许在一个源文件中声明另一个源文件中定义的变量或函数。

**模块化：**通过共享变量或函数使得代码更清晰、模块化、易于维护。

**链接阶段的作用：**在链接阶段解决外部符号的解析。

**与 C++ 互操作：**extern "C" 允许 C++ 代码使用 C 语言的调用约定，使得 C 和 C++ 代码能够互相调用。

**避免多重定义：**通过声明而非定义，避免了重复定义引起的链接错误。
